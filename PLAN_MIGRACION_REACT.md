# Plan de ejecución · Repository Dashboard en React

**Estado al 19 de noviembre de 2026.** Plan para implementar en este repositorio. La referencia funcional es Angular en `1d429d7`. La referencia visual y técnica es Admin UI en `5dacfdb`, sobre harvester `d919a07`, core `0c52e97` y plataforma `693385a`. Las referencias externas de este documento apuntan a esas revisiones para poder seguirlas desde un checkout independiente.

## Resultado y primera entrega

Entregar el dashboard completo en `web/`, con fuentes, traducciones, cliente, lock npm, pruebas y build propios. Reutilizar por copia las partes probadas del admin y registrar origen y SHA en la descripción del cambio que las incorpore. Un checkout aislado del dashboard debe poder ejecutar instalación, pruebas y build. La integración Maven con el harvester seguirá viviendo en el reactor de plataforma.

La primera entrega demostrable es **iniciar sesión por el host dashboard, elegir AREANDINA, abrir el snapshot 6, mostrar su resumen, abrir una regla y recargar esa URL**. Esta entrega valida la identidad, el contrato de lectura, la fidelidad visual y la distribución de los archivos bajo un idioma concreto. Mantener el bundle Angular disponible hasta terminar la matriz de paridad y ensayar la reversión.

Referencia principal: [ApiV5DashboardCompatibilityController](https://github.com/lareferencia/lareferencia-lrharvester-app/blob/d919a0751c81656667f46ca14c26c46e99452b7a/src/main/java/org/lareferencia/backend/api/v5/ApiV5DashboardCompatibilityController.java), incluidos los records Java `Source`, `Harvest`, `Record` y `ValueCount`. Consultar también el [manual de API v5](https://github.com/lareferencia/lareferencia-platform/blob/693385a3158d0a321dbabff9fdf341b3eb6943f0/docs/HARVESTER_MANAGEMENT_API_V5.md) y la especificación que sirve el harvester en `/api/v5/openapi` desde un host autorizado. El [servicio de diagnóstico nativo](https://github.com/lareferencia/lareferencia-lrharvester-app/blob/d919a0751c81656667f46ca14c26c46e99452b7a/src/main/java/org/lareferencia/backend/api/v5/ApiV5DiagnosticsService.java) documenta la otra superficie que usa el admin.

En la tabla, H significa `/api/v5/dashboard/harvesting/source` y V significa `/api/v5/dashboard/validation/source`. Todas son lecturas GET.

| Endpoint | Parámetros y respuesta que se deben validar | Consumidor React |

Ejemplo de contrato que debe convertirse en fixture: `GET /api/v5/dashboard/validation/source/AREANDINA/6/records?valid_rules=5&pageNumber=0&pageSize=10` devuelve una primera página y total de 1.871 registros en la copia documentada. Comparar identificadores y resultados por regla, además del total. Para exportar o abrir GetRecord construir URL con parámetros codificados. Para el portal verificar el ID que espera una instalación real; Angular separa `id` por guion y usa el segundo segmento, comportamiento frágil con otros formatos.

**Límite de la copia directa del admin.** Sus métodos `diagnosticSummary`, `diagnosticRecords` y `diagnosticOccurrences` usan POST en `/snapshots/{id}/diagnostics/…/query`. También solicita `network(id)`, `snapshot(id)` y potencialmente XML. Sustituir esas dependencias en el controlador de página React. Adaptar los DTO en el borde de la aplicación antes de renderizar. Evitar una emulación costosa que descargue todas las páginas para recalcular el resumen.

**Decisiones que pueden cambiar el alcance**:

- Para la primera versión, propuesta de mostrar «Todo el snapshot» en resumen y frecuencias, y «Registros seleccionados» en la tabla filtrada. Si se decide que todo siga la selección, acordar ampliar las lecturas del adaptador y sus pruebas de ámbito antes de cambiar el harvester. Preservar las solicitudes actuales sin filtros y medir el tamaño máximo de la multiselección. Una ruta POST de lectura requeriría contrato CSRF y permiso explícito por ruta en Nginx.
- Preservar el enlace OAI al proveedor y etiquetarlo como tal. XML histórico del snapshot y logs por red son decisiones de acceso independientes. El recorrido básico es ejecutable con la API de lectura actual.
- El CSV de toda una selección paginada, si se requiere, necesita decisiones de volumen, consistencia y tiempo de espera. Documentar el alcance junto al botón incluso en la primera entrega.

### E1 · Construcción autónoma y empaquetado de prueba

[Implementación y verificación local de E1](web/README.md). Build aislado en tres idiomas. El job React queda preparado para la siguiente ejecución de CI.

1. Crear `web/{src,public,tests}`. Organizar `src/app` para bootstrap/router/tema, `src/auth` para sesión, `src/api` para transporte y DTO, `src/features` por pantalla y `src/i18n` por idioma. Crear package y lock y fijar Node/npm como en el admin.
